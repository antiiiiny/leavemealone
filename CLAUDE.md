# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`leavemealone`: a Manifest V3 Chrome/Edge extension for the CHRIST University CUE portal (`https://cue.christuniversity.in/*`). Bunk calculator, absent-hour marking, daily low-attendance alert, and a "Put a bunk" planner. Plain JS in `extension/`, **no build step, no dependencies, no package.json**. Keep it that way unless there's a clear need.

## Commands

- Syntax-check everything: `node --check extension/*.js`
- Quick tests: `calc.js`, `calendar.js` and `plan.js` export via `module.exports` when loaded in Node, so test them ad hoc, e.g.
  `node -e "const C=require('./extension/calc.js'); console.log(C.canSkip(60,80,0.75))"`
  (`plan.js` `require`s `calc.js` and `calendar.js` itself when the globals are absent). There is no test suite or test runner.
- Run: `chrome://extensions` → Developer mode → Load unpacked → `extension/`. After edits, reload the extension and the portal tab. Verifying UI needs the live portal (login required).
- Release: bump `version` in `extension/manifest.json`, push (`.github/workflows/release.yml` refreshes the GitHub zip), then run **Publish to Chrome Web Store** (`.github/workflows/store.yml`, manual or a `v<version>` tag). It uploads `extension/` with `chrome-webstore-upload-cli` and submits it for review; it needs five `CWS_*` repo secrets (never in files). Store versions started at 1.0.0. The live listing id is `komhapklhkoicjaklcanacmnfgcffceb` (`https://chromewebstore.google.com/detail/leavemealone/<id>`).

## Architecture

**Script loading order matters.** No modules: files share globals. Both `manifest.json` content_scripts and `popup.html` load `calc.js` → `calendar.js` → `plan.js` → `ui.js` → `profile.js` → then `content.js` / `popup.js` (`background.js` doesn't need `profile.js`). A new shared file must be added to both lists, in dependency order.

- `calc.js` (`Calc`): pure maths. The university's lines live here once: `Calc.FLOOR` (74.5: medical starts counting, lowest minimum/ESE target), `Calc.DETAIN` (75), `Calc.ESE` (85), `Calc.STALE_DAYS` (3); `Plan.ESE_MIN`/`ESE_OVERALL`, the popup's `STALE_DAYS` and the daily alert read them (`UI.DETAIN`/`SUSEGAD` repeat 75/85 only because `ui.js` also loads alone on the welcome page). `Calc.effective(snap, adj, exc)` is the core: it merges the portal snapshot with the user's adjustments and absent-hour marks into effective per-course and overall numbers. Every view (pill, drawer, popup, planner) should go through it rather than recomputing. The on-page drawer (pill, Overview, Put a bunk, Skip today) uses `Calc.actual(snap, adj, exc, { medInCourse })` = `effective` plus co-curricular hours counted in their own course too (overall counts them once). Medical counts in its own course only while `Plan.medInCourse(medBeforeMse)` is true (setting on and the MSE window not over yet); in the overall it is always the 74.5% to 84.49% band. Every `Calc.actual` caller must pass that option. The toolbar popup and the daily alert use `Calc.actual` too, so every surface shows the same numbers; the popup's Reclassified card lists the marked hours with the portal's own % for comparison.
- `calendar.js` (`Cal`): academic-calendar data (`YEARS`: semesters, holidays, working Saturdays) plus `dayInfo(date)`, `mseWindow(date)` and `cutoff("mse"|"ese", date)` (the last day attendance counts for an exam). `cutoffRef(kind, date)` is the same but keeps answering after the cutoff, until the MSE window ends (or the semester's optional `ese: { from, to }` ends), so the planner can show the numbers that counted; alerts use the strict `cutoff`. Third Saturdays are off unless listed in `workingSaturdays`. Needs a new `YEARS` entry each academic year; otherwise the planner falls back to Mon–Sat minus third Saturdays.
- `plan.js` (`Plan`): pure bunk-planning functions shared by the drawer and popup. `basis` is `now | mse | end`; `thresholdFor(basis, t, esePct)` gives the line and `horizon(basis, from)` the cutoff, and `budgets` / `mseRisks` give the per-course bunk budget. The timetable is keyed by `Date.getDay()`; courses are matched to timetable entries by trimmed, upper-cased name, always through `Plan.courseOf(courses)` (name -> course, cached per `courses` array) or the internal `keyOf`. Don't re-implement the matching. `Plan.periodNum` sorts periods.
- `content.js`: runs on every portal page. The portal is a SPA, so it routes on `location.pathname`: `/main/attendence` (sic) parses the course table and saves a snapshot; `/main/AbsentDetails` handles marking; `/main/absence` (the all-courses list) saves its rows to `absentList` for the popup and shows only a pill, except when the course filter is set to one course, which gets the same marking panel as `/main/AbsentDetails` (course from the filter text, not `lastCourse`); `/main/timeTable` saves the timetable. All injected UI lives in one Shadow DOM host; `ui.css` is fetched via `web_accessible_resources` and injected into it; the bundled Space Grotesk font is declared in the page `<head>` (a shadow root can't load fonts). The drawer shell (`buildShell`) is built once and only its contents are swapped.
  Overview extras: `todayCard` ("Skip today?": next class day from `Plan.upcomingFrom`, per-class verdicts via `Plan.impact`, ticks in `todayPick`) and `needView` (a course row opens, `courseOpen`, to show what it needs with dates from `Plan.courseClasses`). The all-courses absent drawer has a "Mark hours" mode (`absMark`, `markAbs`, `drawAbsBody`) that writes the same `excused[sem][courseKey].rows` as the per-course panel (row key `date|period`, course key `code || name`). With the filter on "All courses", `syncMarksFromList` runs `reconcileMarks` (the same reconciliation as the per-course page) for every course, so portal labels and "updated on the portal" hours show up without opening each course; a list that may be partial never marks hours gone. Both marking views put a whole-day A/C/M/L control (`UI.daySeg`) on any day with 2+ markable hours; it skips hours the portal labelled itself, and in the all-courses view one day can span courses (`markAbs(list, choice)`).
  The Overview IS the actual view: the same layout as before (hero with the number, bar and status lines, Skip today, course list), now fed by `Calc.actual`; one sub line under the status lines says how much you added and what the portal shows (`effPortal = Calc.effective(snap, {}, {})`). Each course row opens (`needView`) to say what it needs and what was counted. The per-hour breakdown lives on the absent pages and the marking panel.
- `ui.js` (`UI`): DOM helper `h`, `semRank` (the latest semester by its trailing Roman numeral), `plural`, icons, chips, bars, segmented pills (with a sliding thumb), stepper, switch, accordion, the number `tween` and the date/period/time formatters (`niceDate`, `nicePeriod`, `startTime`), shared by the drawer and popup. `ui.css` holds the design tokens and every component rule.
  Planner ticks mean "you attend this class", but the planner state is still the set of periods *skipped* per day (`Plan.setAttend` converts). The dock keeps 16px from the portal's own scrollbar (`syncGutter`, the portal scrolls inside a container, not the window).
- `popup.js`: toolbar popup, reads the same storage. It rebuilds everything on each `draw()`, so it restores focus by `data-key` and defers a redraw while a number box (`.stv`) has focus. Settings are grouped (Targets / Counting / Alerts / Your data; `group`, `setRow`); Help & support is its own last block (`helpBlock`); a stale-data banner (> `STALE_DAYS` = 3) sits under the header. Settings has Backup: Export writes `{ app: "leavemealone", schema: 1, version, exportedAt, data }` (the `KEYS` list) to a JSON download; Import (`readBackup`) keeps only `KEYS` and replaces, not merges. Add any new storage key to `KEYS`. `readBackup` drops any snapshot without a `courses` array and numeric `syncedAt` (and a `latest` pointing at one), and `draw()` catches a throw from `drawAll` and shows `drawBroken` ("Couldn't read saved data", Export/Import, and Erase behind a yes/no), so bad saved data can't leave a blank popup. A redraw keeps the control you last touched (`lastKey`, set on pointerdown/focusin) in the same place on screen, because changing the minimum or ESE target changes how tall the cards above Settings are; a fixed `scrollTop` made the popup jump.
- Guided tour: `UI.tour({ mount, steps, onEnd })` dims everything but a hole over one element per step (`data-tour` anchors; a `target` may also be a page element outside the shadow root, e.g. the portal's own "View Details" button). It re-places the hole every frame for ~1s after each step (`follow()`), so an animating drawer can't leave it offset, and shows a segmented progress bar. The popup runs it on the first open with data (`startTour`), the drawer on the first attendance render (`maybeTour`, mounted on the shadow root); each sets `tour.popup` / `tour.drawer` on Done or Skip. Keep the steps' text in sync with the UI. The last step (only if something is missing) starts the **first-run setup**: `runSetup` writes `setup: { s: "tt"|"abs", at }` and goes to the Timetable page; each page's tick calls `setupStep` once its data is saved (timetable -> `/main/absence` -> `/main/attendence`), all in one tab. The flag expires after 10 minutes and is transient (not in `KEYS` or `Profile.DATA`). The popup's version of the step opens one CUE tab first. `content.js` listens to `chrome.storage.onChanged` (attendance page only) so popup settings show up without a reload.
- `profile.js` (`Profile`): several students on one browser. `Profile.who()` reads the logged-in student from the portal header (a `p.MuiTypography-body2` name followed by a `span.MuiTypography-caption` class code like `6BTIT`), `idOf(name)` hashes it. The active person's data stays at the top-level keys (every screen reads those, unchanged); `activate(id)` parks the current person's `Profile.DATA` keys in `profiles[id].data` and swaps in the new one's. `content.js` `tick()` calls `syncProfile()` first and reads or saves nothing until the profile is settled. The first profile on a browser adopts the data already there. The popup shows whoever logged in last; it has no switch (a switch while a CUE tab is open could save one person's portal data into another's profile), only Remove for parked profiles. Settings are shared. **A new per-person storage key goes in `Profile.DATA`.**
- `welcome.html` / `welcome.css` / `welcome.js`: the bundled about page, in the **extension's own look**: it loads `ui.css` (tokens, Space Grotesk, `bar`/`chip`/`seg`/`dbadge`/`btn`/`link`) and `welcome.css` only lays out the page (class names must not clash with `ui.css`, hence `w-top`, `w-actions`). Free-flowing: no section boxes or divider lines; sections are separated by space, a gold `.kicker` label and type. Navy and gold only; green and red appear only inside the demo. The demo (`[data-demo]`, welcome.js) loops: a cursor marks a day C (co-curricular), the overall counts 74.12% -> 76.47% (invented: 63 -> 65 of 85 hours), the bar and chip go red -> green; reduced motion shows the end state. Sections: hello (three steps + the demo), chip in (UPI with a QR thumbnail that opens big in a `<dialog>`; `#support` in the URL opens it straight away) beside build-it-with-us, and a report form that opens `github.com/<repo>/issues/new` with the title and body filled in (the extension sends nothing; the person submits on GitHub, signed in). `background.js` opens it once on a fresh install (`onInstalled` reason `install`, not updates). Publisher name, repo, UPI ID and the not-affiliated line come from `UI.ABOUT` (`ui.js`); the UPI block stays hidden while `UI.ABOUT.upi` is empty. It loads only `ui.js` and must make no network requests (links open in new tabs).
- Popup support: `supportCard()` (from the first popup open, until "Chip in" or "No thanks" sets `supportAsk: "done"`; hidden under the stale warning) and `helpBlock()`, the "Help & support" block that is always last, outside Settings (Chip in, Report a bug, Quick tour, the not-affiliated line).
- `background.js`: daily alarm + notification; it loads `calc.js`, `calendar.js` and `plan.js` with `importScripts` at the top so it can warn about the MSE line (`Plan.mseRisks`).

**State** is all in `chrome.storage.local`, keyed per semester label (the portal's semester combobox text):
- `snapshots[sem]` (portal data), `latest` (highest semester by trailing Roman numeral)
- `adjust[sem]` = `{ cocurricular, courses: { [key]: { att, sch, baseSch } } }`: hours typed in that aren't on the portal yet
- `excused[sem][key]` = `{ rows: [{ k, h, s, p?, gone? }], baseAbsent }`: per-absent-hour marks, `s` ∈ `later | cc | med`
- `lastCourse`: the Absent Details page doesn't say which course it shows, so the course whose "View Details" was last clicked is remembered
- `bunkPlan[sem]` = `[[dayKey, null | [period, ...]], ...]`: the Put a bunk selection, autosaved (`persistPlan`, restored on the first render per semester, past days dropped). It only feeds the Put a bunk tab, never `Calc`, the Overview or the popup. Per person (`Profile.DATA`) and in the backup `KEYS`.
- `tour` (`{ popup?, drawer? }`: which guided tours have been seen), `threshold` (the minimum, per course and overall; MSE is always `Plan.MSE_MIN`), `alerts`, `timetable` (merged per weekday from the one week the Timetable page shows, so a holiday week doesn't wipe days, but only with a timetable from the same semester: `timetableSem`), `ttSchema` (set by `background.js` after its one-time wipe of pre-0.5.0 timetables), `sortBy`, `bunkBasis` (`now | mse | end`, where `end` is ESE), `profile` (active profile id), `profiles` (`{ [id]: { label, data? } }`: label = first name; `data` = a parked person's `Profile.DATA` keys), `eseTarget` (ESE target %, unset = the minimum), `medBeforeMse` (medical counts per course until the MSE is over; unset = on), `supportAsk` (`"done"` once the support card was answered; shared, not in `Profile.DATA` or `KEYS`), `absentList` (`{ sem, at, rows: [{ date, day, period, time, code, name, type, kind, h }] }`, saved from the all-courses absent page; the popup groups it by day)

Course key = `code || name`.

## Attendance rules (easy to break)

The full, current list lives in `docs/attendance_rules.md`; keep it in step with the code. Summary: MSE = every course at 75% (no overall); ESE = overall at 85% (medical helps the overall); "now" = both.

- **Reconciliation:** `baseSch`/`baseAbsent` record the portal's counts at the time of an adjustment. If the portal's count changes, the adjustment is flagged `stale`. Rows the portal itself labels (`p`) are locked; rows it stops listing (`gone`) are already in its numbers and are not counted, pending "Confirm present". Excused hours are scaled so they never exceed the portal's own absent count.
- **Co-curricular** counts as attended in the overall and, through `Calc.actual` (every main number), in its own course too. `Calc.effective` alone keeps it overall-only. When the snapshot has a Co-curricular column (`snap.hasCc`, semester end), the portal has already included it, so the extension adds none.
- **Medical** follows the portal's policy text. It's computed on the aggregate *with* co-curricular: below 74.5% it's not considered, from 74.5% to under 85% it's added to overall attended, and at 85% or more it's not needed. It is not capped at 85%. Per course, medical counts as attended until the MSE window ends (setting `medBeforeMse`, on by default), then resets to not counted.

## Rules

- **Never commit real portal pages or screenshots.** `Pages/` (gitignored) holds saved portal HTML with a real student's name and attendance; use it locally for selector work only. Anonymise or invent any fixture data.
- The extension must make no network requests besides loading its own bundled files (`ui.css`, `fonts/`) (the README's privacy claim depends on it).
- **Unreadable page notice:** if the attendance page has no readable course table for 5 seconds, `noteUnread` (content.js) replaces the pill with a panel: in grid view "Switch to table view" (clicks the portal's own `table view` toggle), otherwise "Couldn't read this page" with Reload, Go to Attendance and Report on GitHub (the Daily Log tab gets "Open Course Overview" only if nothing was saved yet). The next successful read rebuilds the drawer. ESE target: official 85%, editable from 74.5 to 100 (`Plan.ESE_MIN`; `Plan.eseOf` clamps; the stepper takes `decimals: 1`). Below 85 it is allowed but flagged: `UI.eseFlag` shows a red "fine you will pay uh?" line under the control (Settings, planner) and the popup's exam card says it is under the official figure. The popup stepper saves on blur/Enter/+- (not while typing), Reset removes the key, and the exam card shows how far the overall is above/below it.
- **Grid view is read too.** `parseCourses` reads the table, or, in grid view, the course cards (`CARD`, `parseCard`: role=button, aria-label "NAME (CODE): 87.5% attendance, 14 of 16 classes attended."). Grid has no absent or Co-curricular column: absent = scheduled - attended, and `hasCc` keeps what the last table read said. A click on a card remembers the course like "View Details". The **Daily Log** tab has no course data, so `tickAtt` shows the last saved read for that semester (no error panel). The overall % is shown to 2 decimals like the portal.
- **Semester label:** the portal now labels semesters "SEMESTER - VI [On Roll]" / "[Semester Completed]". `semester()` strips the bracket (storage keys stay "SEMESTER - VI"), `UI.semRank` ignores it, and `tickAtt` moves any key saved with the bracket to the plain label (`plainKeys`). **Minimum %** is clamped to 74.5 to 100 everywhere it is read (`Plan.minOf`).
- **Bug reports carry safe diagnostics:** `UI.diag` builds lines (version, page, which view was read, counts, semester label, a "found" line from the DOM) with **no names, hours or percentages**. The welcome form adds them when "Add technical details" is ticked (read from storage; `snap.via` records table or grid); the "couldn't read this page" panel's "Report it on GitHub" builds the same with `reportUnread`. The person reviews the GitHub issue and submits it; the extension sends nothing.
- **Idle ticks are cheap:** the MutationObserver fires on every portal DOM change, so `tickAtt`, `tickAbs` and `tickTt` return early when the page reads the same as last tick (`lastRead`, `absQuick`, `ttSeen`; 30s cap so "synced" still refreshes). A change in settings clears `lastRead` so it re-renders.
- **Accessibility:** any element given class `h3` becomes `role="heading" aria-level="3"` inside `UI.h` (use that class for section titles, not a bare div); the drawer's two tabs point at one `role="tabpanel"` (`#cue-panel`, labelled by the showing tab via `aria-labelledby`). Checked live on the portal: every control has a name, none is under 24px, and every keyboard-focusable one shows a focus ring (`.cue :focus-visible`); keep it that way.
- Portal markup changes; selectors like `table[aria-label="coursewise attendance table"]` and the grid cards' `aria-label` are the fragile part.

- **Storage defaults must not be `undefined`.** `chrome.storage.local.get({ key: undefined })` drops the key from the request, so a saved value is never read back (this is why the ESE target silently reset to 85 on every redraw). Use `null` and treat it as unset (`Plan.eseOf`). The popup smoke test's fake storage (`docs/checks/check9.js`) mimics this.

## Copy and tone

- The voice is Bangalore college slang: "bunk", never "skip" ("Put a bunk" tab, "can bunk 3", "no bunks left").
- **Slang tags** have four tiers on fixed lines, not the user's minimum (`UI.tierOf`; lines `UI.DETAIN` 75, `UI.STEADY` 80, `UI.SUSEGAD` 85), one word each, each with its own look in `ui.css`: low (red) "pakka detain", wavy underline; tight (orange) "eda mone", dotted underline and a slight forward lean; steady (yellow, the only use of `--steady`) "mastundhi", one straight underline; relaxed (green) "susegad" (Goan), leaning back. The pill drops the underlines. Under the user's own minimum the best tag is "tight" (never steady/relaxed beside "below your minimum"). The pill shows the overall's tag when it is low, else "N low" if some course is below the minimum, else the overall's tag. Render only through `UI.vibeTag` / `UI.vibeLead` (`.vibe`: quiet italic aside, no fill or icon). The can-bunk / attend chips (`.chip`) must stay the loudest element; never style a joke as a chip. Course rows: the slang tag sits on the right, under the percentage + chip (`.pcw` wraps `.pc` + tag; the popup's what-if `.rr` holds it too), in the space beside the code, so a row stays compact; the left side is name, then code + ADJ (`.cl`, which wraps if it must). `.pc` and `.rr` are pinned to the name's first line, so nothing runs under the percentage. Row rhythm: the left block is `.cname` (always at least 40px: name line + code line, starts at the top) and `.cl` is at least 21px (the height of the ADJ chip), so every one-line row has the same top, gap and bar position (with or without a code or ADJ), and a two-line name only adds one line; `.pcw` stretches to the row with the chip on top and the tag at the bottom, level with the code line.
- One-sentence captions, help lines and toasts end without a period; multi-sentence paragraphs keep theirs. No exclamation marks. The footer `UI.TAGLINE` keeps its period on purpose.
- Tour steps take `text` as a string or an array with nodes; `.tour-em` (red, underlined) highlights the one action to take.

## Look (unslop pass)

- Navy surfaces, **gold is the one accent** (`--pick`/`--gold`: selection, ticks, switches, your marks). Green/amber/red mean good/warn/bad only. Holiday and medical are neutral on purpose. New colours need a reason; don't add hues.
- Depth comes from surface steps, not effects: cards use `--layer` + `--hi` (top highlight) + `--edge` hairline; things pressed into a card (bars, calendar days, steppers, switches, segmented controls) use `--well`. The Overview/popup hero number sits on the drawer without a card (`.hero`; `.hero.plan` stays boxed as the result card).
- No glows, colour washes, cursor spotlights, pulsing rings or hover tilt/lift. Motion that stays: tab thumb, number tween, bars growing, accordion, pill orbit on click.
- Weights are 500; only chips keep 600. Chips stay caps and tracked on purpose.
